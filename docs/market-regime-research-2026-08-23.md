# Binance USD-M 永续市场 regime 调研（2026-08-23）

## 结论

截至本次可获得的最后一个完整 UTC 日 `2026-08-21`，没有证据表明过去六周已经发生了一个
持续数周、方向一致的全市场成交活跃度 regime 切换。更准确的描述是：

- `2026-07-11` 至 `2026-08-21` 的 522 个固定合约面板中，最后 14 日相对最初 14 日的
  单币成交额中位变化比为 `0.980`；`49.0%` 的合约上升，`38.1%` 的合约下降至少 `20%`。
  横截面没有形成一致方向。
- 同期单币交易数中位变化比为 `1.095`，`54.6%` 的合约上升。交易数整体略有上移，但
  breadth 不足以支持一次全市场同步切换。
- 六个连续自然周的全市场日成交额中位数在 `21.845B` 至 `28.441B USDT` 之间来回波动，
  没有形成连续的台阶式上移或下移。
- 但 `2026-08-19` 至 `2026-08-21` 出现了一个新的广泛活跃度冲击：相对此前 14 日，
  522 个合约的最近三日成交额中位变化比为 `1.678`，`77.8%` 上升；交易数中位变化比为
  `1.605`，`76.8%` 上升。它只有三个完整日，当前只能标记为 **broad shock pending**，
  不能称为已经确认的新 regime。

因此，generation 7.0 的 11 个 core 变化不能主要归因于一次全市场 regime 切换。它们更像是
单币分化、门禁语义和一次全量 bootstrap 重选共同作用的结果。市场级检测与单币成员决策应
分别建模，不能让同一个单币状态机同时猜测两件事。

## 方法

Binance 日 K 线数组的第 8 个字段（索引 7）是 quote asset volume，第 9 个字段（索引 8）
是 number of trades。本报告将它们分别称为“USDT 成交额”和“交易数”。它们是成交活跃度
指标，不等价于盘口深度，也不证明某一名义金额可以低冲击成交。

分析使用三组互补口径：

- **市场总量**：每天对固定面板求和，再对每个 7 日或 14 日分段取日中位数。
- **横截面水平**：先对每个合约在分段内取中位数，再报告 522 个合约的 P25/P50/P75。
- **breadth**：对每个合约分别计算末段与首段的中位数比，统计同方向合约占比。总量可以被
  BTC、ETH 等头部合约主导，breadth 用来判断变化是否真正在市场中广泛发生。

为避免事后把普通波动命名为 regime，本报告采用一个仅用于诊断、尚未写入生产协议的判据：
方向一致的合约占比至少 `70%`、横截面中位变化至少 `25%`，并且至少持续两个完整 7 日块，
才称为“已确认的市场级变化”。只达到幅度和 breadth、尚未达到持续时间的，称为 pending
shock。这个判据需要更长历史回测后才能成为正式参数。

## CV 门禁在冲击期的含义

冻结的 523 个完整 14 日合约中，quote-volume CV 的 P25/P50/P75/P90 分别为
`0.527/0.700/1.081/1.627`。有 85 个合约通过全部成交额和交易数绝对门槛；其中 14 个
仅因为 `CV > 1.2` 被活动门禁排除，占这组绝对合格候选的 `16.5%`：

```text
ENAUSDT BOMEUSDT BCHUSDT AKEUSDT GWEIUSDT BTWUSDT BICOUSDT MMTUSDT
TRUMPUSDT TUTUSDT BLESSUSDT MUBARAKUSDT TSTUSDT HUSDT
```

CV 对向上和向下偏离同样敏感。窗口末尾的全市场活动冲击会抬高包含“冲击前低位”和“冲击后
高位”的单币 CV，即使最近成交额是在增加。`ENAUSDT` 的末 14 日成交额中位数为 `53.333M`
但 CV 为 `2.056`；`AKEUSDT` 的中位数为 `52.270M`、CV 为 `1.600`。把这类结果解释为
“单币质量已经失效”是不成立的。

因此 CV 可以作为稳定性评分或人工诊断项，但不应单独触发 core 紧急退出。硬留任应依赖连续
完整日的下尾成交额、交易数和盘口可用性；处于 market `SHOCK_PENDING` 时，CV 造成的普通
排名轮换应冻结。若研究确实要惩罚流动性下降，应使用只针对下行的证据，而不是对称 CV。

## generation 7.0 变化为何不是一个市场 regime 事件

被移出的 11 个 core 在六周窗口中的行为方向并不一致。例如：

| 合约 | 末 14 日 / 首 14 日成交额 | 末 14 日成交额中位数 | 末 14 日 CV | 解释 |
|---|---:|---:|---:|---|
| ESPORTSUSDT | 0.087 | 8.094M | 0.509 | 单币活跃度大幅下降 |
| DEXEUSDT | 0.140 | 14.951M | 0.292 | 仍较稳定，但相对排名降到 boundary |
| BCHUSDT | 0.428 | 23.776M | 1.651 | 绝对成交额仍高，CV 被少数高活动日拉高 |
| ENAUSDT | 0.748 | 53.333M | 2.056 | 高成交额但高 CV，不能解释为低流动性失效 |
| EULUSDT | 13.638 | 10.863M | 0.370 | 活跃度显著上升，但排名仅到第一备用 |
| ONUSDT | 3.424 | 18.062M | 0.610 | 成交活跃度上升，最终失败来自瞬时盘口深度门禁 |

进入 core 的币也不是全部处在同一方向：`CYSUSDT` 的成交额中位数增加约 `271` 倍，
`ACEUSDT` 增加约 `19.8` 倍，但 `LABUSDT` 只有首段的 `0.112` 倍，`JTOUSDT` 为 `0.723`
倍，`XPLUSDT` 为 `0.742` 倍。全量 bootstrap 按当前 14 日分位数、交易数、CV 和当前盘口
共同重排，自然可能产生较多角色变化；这不是市场 regime 检测器给出的批量换币信号。

使用当前门禁中的成交额与交易数部分（不含没有历史序列的 spread/depth）滚动计算 14 日
通过数量，五个窗口依次为 `77、71、73、72、70`。候选容量有所收缩，但没有断崖式崩塌。
这也说明 `stable_pool=59` 不能单独当作 regime 指标：它还包含瞬时盘口门禁，并在最终统计
中排除了被分配给 probe 的合约。

## 对决策机制的含义

不要把市场状态塞进单币的 `HEALTHY -> SUSPECT -> ...` 链。更简单且职责清晰的设计是两层：

1. **Market context 只做描述和节流**：每天从固定宽面板计算总量、横截面变化、breadth 和
   持续时间，输出 `NORMAL`、`SHOCK_PENDING` 或 `SHIFT_CONFIRMED`。它不直接决定哪个币退出。
2. **Symbol eligibility 只回答证据是否可用**：下线、历史缺失或盘口响应不可解析时不能参与
   decision；成交额、交易数、点差与 depth 不设绝对门槛，而是在证据完整的池内做横截面排名。

市场 context 对成员机制的唯一作用应是：`SHOCK_PENDING` 时冻结非必要的排名轮换、继续采集
证据；`SHIFT_CONFIRMED` 时恢复有审计记录的常规评估。单币下线始终可以独立处理。这样无需
单币多阶段状态机，只需保存市场观察、完整证据、成员停留时间和最终 decision。

## 数据限制

- Binance 公共 K 线提供历史成交额和交易数，但公共 order-book 端点只给请求时刻的快照。
  冻结包的 3 轮 depth 和 5 轮 bookTicker 只能描述 `2026-08-22` 附近，无法判断过去六周
  是否发生盘口深度、点差或滑点 regime 变化。因此本报告的“regime”严格指成交活跃度。
- 当前快照中接受深度采样的 72 个合约，其最大点差的横截面中位数为 `1.48 bps`，P10/P90
  为 `0.24/4.83 bps`；三轮采样中 `+/-10 bps` 较薄一侧深度的逐币最小值中位数约
  `13.7K USDT`，P10/P90 约为 `1.02K/220.5K USDT`。这只能证明当前单币盘口高度异质，
  不能提供历史变化方向；`limit=100` 也可能截断极深盘口的带宽累计值。
- 固定面板由 `2026-08-22` 仍在证据集中的合约构成，会遗漏窗口中途已经退市的合约，存在
  终点存活偏差。它适合判断当前可选市场的共同变化，不等同于历史上每一天的完整挂牌市场。
- `DOSUSDT` 的新增历史 K 线证明 Binance API 可能回填数据。生产决策必须继续冻结原始响应和
  source hash；事后研究应报告查询时间，不能假定同一个 URL 永久返回同一组历史行。
- 日 K 线中的 number of trades 是交易所返回的成交事件计数，不是独立交易者数量。
- 最近三日冲击位于样本末端。任何“新 regime 已形成”的结论都必须等待更多完整日，不能
  用未完成的 `2026-08-22` K 线补足持续时间。

## 可复现抓取

以下命令重建本次 42 日响应。`endTime` 使用最后完整日的最后一毫秒，避免混入未完成日：

```bash
ARCHIVE=dist/v0.3.7/formal-universe-7.0-20260822T015604Z.sources.tar.gz
WORK_DIR=$(mktemp -d /tmp/ft-market-regime.XXXXXX)
tar -xzf "$ARCHIVE" -C "$WORK_DIR"
mkdir -p "$WORK_DIR/42d"

gzip -cd "$WORK_DIR/daily-klines.json.gz" |
  jq -r '.symbols | keys[]' |
  while IFS= read -r symbol; do
    curl -fsS --retry 3 --get \
      --data-urlencode "symbol=$symbol" \
      --data-urlencode 'interval=1d' \
      --data-urlencode 'startTime=1783728000000' \
      --data-urlencode 'endTime=1787356799999' \
      --data-urlencode 'limit=60' \
      'https://fapi.binance.com/fapi/v1/klines' \
      > "$WORK_DIR/42d/$symbol.json"
  done
```

复算时只保留恰好具有 42 个预期 open time 的合约。对每根 K 线读取 `[7]` 和 `[8]`，按上述
7 日、14 日窗口分别执行 sum、median、线性插值 P25/P75 和逐币比值统计。报告中对旧选择器
的复算仅用于解释 generation 7.0 的历史形成过程，不是 v0.3.8 的生产规则。
